# 8. 複数人格を混ぜないための設計（マルチペルソナ）

複数のAIキャラ（GM・複数NPC・将来のAI仲間PC）を登場させる際に、
「人格が溶け合う／素のモデルに回帰する／全員が中央値へ収束する」を防ぐための方針。
出典はユーザー作成の設計メモ。本書はそれを**このプロジェクトの構造に対応づけ**、
「既にできていること／今やること／Phase 2 で入れること」を切り分ける。

## 8.1 中心原則：LLMはステートレスな「発話関数」
記憶はホスト（エンジン）側が権威を持って全保持し、LLMには毎ターン
「固定の人格設定 + その時必要な文脈」を渡して**一発の発話**を返させる。
LLMに累積文脈を持たせない → 累積汚染も対話収束も原理的に起きにくい。

```
エンジンが全履歴を保持
  → 毎ターン [固定の人格A] + [エンジンが組み立てた会話状態] を投げる
  → LLM は新品の文脈で人格どおり一発返す
  → 結果をエンジンが履歴に追加
```

## 8.2 現状（このコードで既に満たしている点）
- **GM・NPCはステートレス呼び出し**：[`internal/gm`](../internal/gm/gm.go)・[`internal/npc`](../internal/npc/npc.go)
  は毎ターン、現在の状態から system+prompt を組み立て直す。LLM側に会話履歴を蓄積しない
  （[`internal/llm`](../internal/llm/client.go) は Ollama へ都度 system+prompt を送るだけ）。
- **人格は毎ターン丸ごと投げ直す**：NPCの人格テンプレートを毎回システムプロンプトに展開。
- **口調の暴走の一次対策**：NPCに「設定外の口癖・方言を足すな」を明示済み。
- → メモが警戒する「累積汚染／収束」は、**1体ずつのNPC会話では現状ほぼ発生しない**。

## 8.4 会話メモリ（今入れられる土台）
NPCは現在、直前のプレイヤー発言しか見ていない（前のやり取りを覚えていない）。
エンジン側に「シーン内の会話履歴」を持たせ、NPCへ **[これまでの要約] + [直近の生ログ数行]** を渡す。

- 記憶の主体はエンジン。LLMには都度、短い文脈として提示するだけ。
- 生ログは人間ターンをまたぐたびにリセット（上限がかかる＝収束の燃料が無限に伸びない）。
- 要約は当面「直近Nターンの生ログをそのまま渡す（要約なし）」で代用し、
  Phase 2 で本物の裏要約（軽量LLM・人間ターンの空き時間）に差し替える。

## 8.5 Phase 2 で入れる重い機構（混線が実際に起きてから）
AI仲間PC同士・NPC同士を会話させる段階で、メモの中核を実装する。
- **裏要約**：人間の入力待ち時間に軽量LLMで会話を3行要約し確定保存。
  トリガーは「人間ターン」＋「生ログがNターン蓄積」の併用。間に合わない時の代替動作も決める。
- **二段バリデータ**：①口調（ルール・安価・前段）→ ②態度・意図（LLM判定・後段）。
  生成役と判定役を分け、理由付きで差し戻す。**リトライ上限＋フォールバック定型句**を必ず用意。
- **過剰厳格化を避ける**：人格の「芯（絶対に外せない一線）」だけを判定対象に。揺らぎは許す。
- **プロンプトキャッシュ**：固定の人格Aをキャッシュ、可変の要約だけ差し替えてコスト・遅延を削る。
- **（任意）系統違いのモデル割当**：人格ごとに別ファミリー（Llama/Mistral/Qwen/Gemma…）を当て、
  同一ベース起因の似通いを構造的に消す。VRAMはホットスワップ／プリロードで実用域に。
